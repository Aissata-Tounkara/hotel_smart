Présentation du projet

Le cahier des charges

Hotel Smart a été développée dans le cadre d'une épreuve de l'Olympiade WorldSkills Algérie, avec pour mission de concevoir en trois jours une application mobile Flutter complète de gestion hôtelière pour un établissement fictif, Le Palace (4 étoiles, Alger).

Trois profils aux permissions distinctes

ProfilAccès
AdministrateurGestion complète : utilisateurs, chambres, statistiques, tableau de bord
RéceptionnisteGestion opérationnelle : chambres, réservations, clients, paiements, check-in/out
ClientConsultation uniquement : ses propres réservations et son profil

Stack technique imposée

Dart / Flutter, base de données locale SQLite (sqflite), intégration d'une API REST externe (nationalités), gestion d'état avec provider, Material Design 3, versioning Git avec un commit par partie terminée.

Déroulé de la mission

  1. Jour 1 — Conception (diagrammes UML, wireframes), initialisation du projet, base SQLite et première version fonctionnelle (connexion + tableau de bord basique).
  2. Jour 2 — Authentification par rôles, CRUD complet chambres / réservations / clients, intégration de l'API externe.
  3. Jour 3 — Statistiques, notifications locales, paiements, profil et paramètres, tests unitaires, documentation et build de l'APK final.
Livrables attendus et fournis : diagrammes de classes et de cas d'utilisation, application entièrement fonctionnelle (CRUD, rôles, notifications, statistiques), suite de tests unitaires, documentation technique, manuel utilisateur et APK de release.
Présentation du projet

L'architecture choisie

L'application suit une architecture en couches stricte, qui sépare l'interface, l'état observable et l'accès aux données : chaque couche ne connaît que celle immédiatement en dessous, ce qui permet de tester la logique métier indépendamment de l'UI et de faire évoluer une couche sans toucher aux autres.

UI (screens/widgets)
   -> Providers (ChangeNotifier) : état observable par l'UI
      -> Services : logique métier (peut combiner plusieurs repositories)
         -> Repositories : un par table SQLite, CRUD brut
            -> DatabaseHelper : Singleton, ouverture/création de la base

Pourquoi ce choix

  • Providers (provider/ChangeNotifier) imposés par le cahier des charges : état simple à observer depuis les écrans, sans boilerplate excessif pour la taille du projet.
  • Services isolent la logique métier réutilisable (hachage de mot de passe, détection de conflits de dates, calculs statistiques) des repositories, qui restent de simples exécutants CRUD.
  • Repositories centralisent tout accès SQLite : un changement de source de données (ex. API distante) n'impacterait que cette couche.
  • DatabaseHelper en Singleton garantit une connexion SQLite unique et cohérente pour toute l'application.

Cette structure se retrouve à l'identique dans l'arborescence du code (models/, services/, repositories/, providers/, screens/...) — voir le chapitre 13 pour le détail complet.

Les fonctionnalités clés

Aperçu visuel des fonctionnalités les plus représentatives de l'application — le détail de chacune est couvert dans le guide d'utilisation (Partie I).

Partie I · Guide d'utilisation

1. Premiers pas : se connecter

Ce chapitre vous accompagne pour votre toute première connexion à l'application, que vous soyez Administrateur, Réceptionniste ou Client.

  1. Lancez l'application Hotel Smart sur votre téléphone.
  2. Sur l'écran de connexion, saisissez votre email et votre mot de passe.
  3. Appuyez sur Se connecter. Vous êtes redirigé vers le tableau de bord adapté à votre rôle.

Écran de connexion : identité bleu nuit / or, champs soulignés et motif Art Déco en arrière-plan.

Compte Administrateur fourni par défaut au premier lancement :
Email : admin@hotelsmart.dz — Mot de passe : Admin@123

Un compte Réceptionniste ou Client doit être créé par un Admin depuis l'écran Utilisateurs (voir chapitre 6).

Partie I · Guide d'utilisation

2. Le tableau de bord et les notifications

Après connexion, le tableau de bord affiche un message de bienvenue, des cartes de statistiques (Admin/Réceptionniste), une grille d'accès rapide adaptée à votre rôle, et une cloche de notifications.

  1. Consultez en un coup d'œil les chambres disponibles/occupées, les réservations du jour et le chiffre d'affaires du mois.
  2. Surveillez la cloche en haut à droite : un badge rouge apparaît dès qu'une réservation arrive ou part aujourd'hui.
  3. Appuyez sur la cloche pour afficher la liste des alertes non lues, et marquez-les comme lues une fois traitées.
  4. Tirez l'écran vers le bas (pull-to-refresh) pour rafraîchir statistiques et notifications à tout moment.

Le badge sur la cloche et le panneau des alertes non lues, ouvert directement depuis le tableau de bord.

En complément, une notification système Android s'affiche automatiquement pour chaque check-in/check-out du jour, même en arrière-plan.

Partie I · Guide d'utilisation

3. Gérer les chambres

Accessible aux profils Administrateur et Réceptionniste.

  1. Ouvrez Chambres depuis l'accès rapide du tableau de bord.
  2. Basculez entre vue Carte et vue Liste via l'icône en haut à droite.
  3. Recherchez une chambre par numéro ou type (mise à jour en temps réel), ou filtrez par type, statut et/ou plage de prix.
  4. Appuyez sur + pour ajouter une chambre : renseignez numéro, type, prix par nuit, étage, statut initial (description optionnelle).
  5. Pour modifier ou supprimer une chambre existante, utilisez le menu sur sa carte (ou le menu ⋮ en vue liste).

Chaque carte affiche le numéro, le type, le prix par nuit et le statut courant (Disponible, Occupée ou Maintenance).

Formulaire d'ajout : numéro, type, prix, étage et statut initial sont obligatoires ; la description est optionnelle.

Le même formulaire, pré-rempli, permet de corriger le prix ou de changer le statut (par exemple repasser une chambre en Maintenance).

Partie I · Guide d'utilisation

4. Gérer les réservations

Accessible aux profils Administrateur et Réceptionniste.

  1. Ouvrez Réservations, puis appuyez sur + pour en créer une nouvelle.
  2. Choisissez un client, une date d'arrivée puis une date de départ : les chambres disponibles pour cette période s'affichent automatiquement (les chambres en conflit de dates ou en maintenance sont exclues).
  3. Sélectionnez une chambre : le montant total se calcule automatiquement (prix par nuit × durée du séjour), puis confirmez.
  4. Filtrez la liste par statut grâce aux chips en haut de l'écran : Toutes, En attente, Confirmée, Annulée, Terminée.
  5. Sur une réservation En attente le jour de l'arrivée, appuyez sur Check-in : la réservation passe « Confirmée » et la chambre « Occupée ».
  6. Sur une réservation Confirmée le jour du départ, appuyez sur Check-out : la réservation passe « Terminée » et la chambre redevient « Disponible ».
  7. Annuler est disponible tant que la réservation est En attente.

Le filtre « Toutes » montre chaque réservation avec son statut coloré ; le bouton d'action affiché (Check-in ou Check-out) dépend du statut courant.

Partie I · Guide d'utilisation

5. Gérer les clients

Accessible aux profils Administrateur et Réceptionniste.

  1. Ouvrez Clients, puis appuyez sur + pour ajouter une fiche (ou sélectionnez un client existant pour la modifier).
  2. Renseignez nom, prénom, téléphone, email et nationalité. Le CIN/passeport est optionnel.
  3. La liste des nationalités se charge depuis internet ; si vous êtes hors connexion ou que le service est indisponible, une liste de secours locale s'affiche automatiquement avec un bouton Réessayer — le formulaire n'est jamais bloqué.
  4. Retrouvez rapidement une fiche via la recherche par nom, téléphone ou email.

6. Gérer les utilisateurs (Admin)

Réservé au profil Administrateur.

  1. Ouvrez Utilisateurs puis appuyez sur + pour créer un compte : nom, email, mot de passe et rôle (Admin, Réceptionniste ou Client).
  2. Si le rôle choisi est Client, liez le compte à une fiche client déjà créée (chapitre 5) — c'est cette liaison qui permet au client de se connecter et de ne voir que ses réservations.
  3. Modifiez ou supprimez un compte directement depuis la liste (icône corbeille).

Liste des comptes utilisateurs, avec leur rôle et l'action de suppression.

Formulaire de création : nom, email, mot de passe (avec confirmation) et rôle.

Partie I · Guide d'utilisation

7. Gérer les paiements

Accessible aux profils Administrateur et Réceptionniste.

  1. Ouvrez Paiements, puis appuyez sur +.
  2. Sélectionnez la réservation concernée : le montant se pré-remplit automatiquement avec le montant total de la réservation.
  3. Choisissez la méthode (Espèces, Carte...) et le statut, puis enregistrez.
  4. Pour changer le statut d'un paiement existant (Payé / En attente / Remboursé), appuyez dessus dans la liste.

Le montant se pré-remplit avec le montant total de la réservation sélectionnée ; méthode et statut restent modifiables.

Chaque paiement affiche le client, la méthode, la date et le montant, avec un badge de statut.

Partie I · Guide d'utilisation

8. Consulter les statistiques

Réservé au profil Administrateur.

  1. Ouvrez Statistiques depuis l'accès rapide.
  2. Consultez le chiffre d'affaires du mois et le taux d'occupation moyen en cartes de résumé.
  3. Faites défiler pour voir le graphique du taux d'occupation des 6 derniers mois, puis celui des revenus cumulés par type de chambre (Simple, Double, Suite).

9. Espace Client : mes réservations

Vue réservée au profil Client.

  1. Connectez-vous avec votre compte Client.
  2. Ouvrez Mes réservations : seules vos propres réservations (chambre, dates, montant, statut) s'affichent.
  3. Si l'écran reste vide alors que vous avez réservé, votre compte n'est probablement pas encore lié à une fiche client — contactez la réception.
Partie I · Guide d'utilisation

10. Profil et paramètres

  1. Ouvrez Mon profil depuis l'accès rapide (disponible pour tous les rôles).
  2. Modifiez votre nom, votre email ou votre mot de passe (une confirmation est demandée), ou déconnectez-vous.
  3. Appuyez sur l'icône engrenage pour ouvrir Paramètres : choisissez le thème (Clair / Sombre / Système) et la langue (Français / العربية).
  4. Le changement de langue applique automatiquement le sens de lecture (RTL en arabe) et traduit les écrans principaux.

11. Questions fréquentes

J'ai oublié mon mot de passe. Un Admin peut modifier votre compte depuis l'écran Utilisateurs.

Je ne peux pas supprimer une chambre ou un client. Vérifiez qu'aucune réservation active n'y est liée ; en cas de doute, contactez un Admin.

Un message « liste hors-ligne » s'affiche sur le champ nationalité. C'est normal sans connexion internet ou si le service est momentanément indisponible : une liste de secours locale (30 nationalités courantes) est utilisée automatiquement pour ne jamais bloquer la création d'un client. Appuyez sur Réessayer une fois la connexion rétablie.

Je ne reçois pas de notification de check-in/check-out. Vérifiez que la réservation concernée a bien une date d'arrivée (ou de départ) égale à aujourd'hui et que son statut est encore « En attente » (check-in) ou « Confirmée » (check-out) : une fois l'action déjà effectuée, l'alerte correspondante ne se déclenche plus.

Hotel Smart est une application mobile Flutter de gestion hôtelière conçue pour l'hôtel fictif Le Palace (4 étoiles, Alger). 13. Architecture logicielle

L'application suit une architecture en couches strictes :

UI (screens/widgets)
   -> Providers (ChangeNotifier) : état observable par l'UI
      -> Services : logique métier (peut combiner plusieurs repositories)
         -> Repositories : un par table SQLite, CRUD brut
            -> DatabaseHelper : Singleton, ouverture/création de la base

Cette séparation permet de tester les services et les modèles indépendamment de l'UI, et de changer la source de données sans réécrire les écrans.

Structure des dossiers

lib/
├── models/        Utilisateur, Client, Chambre, Reservation, Paiement, NotificationAlerte
├── services/      AuthService, ApiService, ReservationService, StatisticsService, NotificationService
├── repositories/  UserRepository, ClientRepository, RoomRepository, ReservationRepository, PaymentRepository, NotificationRepository
├── providers/     AuthProvider, RoomProvider, ClientProvider, ReservationProvider, PaymentProvider,
│                  UserProvider, StatisticsProvider, NotificationProvider, SettingsProvider
├── database/      DatabaseHelper (Singleton SQLite)
├── screens/       auth/, dashboard/, rooms/, reservations/, clients/, users/, payments/, profile/, settings/, statistics/
├── widgets/       StatusBadge, EmptyState, confirm_dialog...
├── utils/         app_theme, constants, validators, ui_helpers, app_strings
└── routes/        app_routes.dart (navigation nommée)

Décisions de conception notables

  • Utilisateur vs Client : le compte de connexion (Utilisateur) est volontairement séparé de la fiche hôtel (Client) ; leur liaison est manuelle, effectuée par un Admin, jamais automatique.
  • Statistiques calculées à la volée, sans table dédiée, pour éviter toute désynchronisation avec les données sources.
  • Compte Admin par défaut créé automatiquement au premier lancement pour ne jamais bloquer l'accès à l'application.

16. Schéma de la base de données

6 tables SQLite, clés étrangères actives via PRAGMA foreign_keys = ON :

users (id, nom, email UNIQUE, mot_de_passe_hache, role, client_id -> clients.id, date_creation)
clients (id, nom, prenom, telephone, email, nationalite, cin, date_creation)
rooms (id, numero UNIQUE, type, prix_par_nuit, statut, description, etage)
reservations (id, client_id -> clients.id, room_id -> rooms.id, date_arrivee,
              date_depart, statut, montant_total, date_creation)
payments (id, reservation_id -> reservations.id, montant, statut, methode, date_paiement)
notifications (id, reservation_id -> reservations.id, type, titre, message, date_alerte, lue)

Suppressions en cascade : supprimer un client ou une chambre supprime les réservations liées (et donc paiements/notifications liées). Ce choix simplifie la cohérence des données pour une application de gestion mono-établissement.

Optimisation des requêtes : des index sont créés sur toutes les clés étrangères ainsi que sur les dates de réservation (idx_reservations_dates) afin d'accélérer les recherches de conflits de dates et les jointures/filtrages les plus fréquents.

17. Rôles, gestion des erreurs et cas limites

Rôles et permissions

AuthProvider expose des getters dérivés du rôle de l'utilisateur connecté (estAdmin, estReceptionniste, estClient, peutGererOperations). Les écrans utilisent ces getters pour masquer/afficher les actions, restreindre la navigation et filtrer les données visibles.

Gestion des erreurs et cas limites

  • Réseau : en cas d'échec de l'appel à l'API de nationalités, une liste de secours locale de 30 nationalités est utilisée automatiquement, avec un bouton « Réessayer ». Le formulaire client n'est jamais bloqué.
  • Métier : les erreurs (AuthException, ReservationException) sont affichées via des messages clairs.
  • Formulaires et données incohérentes : validation côté client (champs obligatoires, format email/téléphone, mot de passe, valeurs numériques positives) avant tout appel à la base de données.
  • Base vide au premier lancement : un compte Admin par défaut est inséré automatiquement à la création de la base.
Compte Admin fourni par défaut : admin@hotelsmart.dz / Admin@123

19. Annexe — Scénario de démonstration (5 minutes)

  1. Connexion Admin (admin@hotelsmart.dz / Admin@123) → tableau de bord avec statistiques dynamiques.
  2. Chambres : recherche temps réel, filtres, bascule Carte/Liste, création d'une chambre.
  3. Clients : création d'un client, liste des nationalités en ligne avec repli local en mode avion.
  4. Réservation : détection automatique des chambres disponibles et calcul automatique du montant.
  5. Check-in / Check-out : la chambre passe « Occupée » puis « Disponible » ; notification générée.
  6. Paiement : enregistrement d'un paiement pour la réservation.
  7. Statistiques : graphiques taux d'occupation et revenus par type de chambre.
  8. Utilisateurs : création d'un compte Client lié à la fiche créée plus tôt, puis connexion avec ce compte pour vérifier la restriction d'accès.
  9. Paramètres : bascule thème clair/sombre et langue FR/AR (RTL).
Points forts à mentionner : compte Admin par défaut au premier lancement, gestion explicite des erreurs réseau, vérification des conflits de dates, index SQLite sur toutes les clés étrangères, suite de tests unitaires passante, flutter analyze sans avertissement.
